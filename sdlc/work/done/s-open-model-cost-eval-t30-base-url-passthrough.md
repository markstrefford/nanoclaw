# t30 — Let the container target a custom OpenAI-compatible endpoint (Moonshot/Kimi)

## Outcome

Make it possible to point the agent at Kimi's endpoint, not just OpenAI's.

## Acceptance

- Setting the Moonshot/Kimi base URL in `.env` causes the agent container to send
  its model calls to that endpoint instead of `api.openai.com`.
- With the Kimi base URL, API key, and model name configured, a group message
  produces a reply generated by Kimi (verified in logs).
- Default behaviour is unchanged when the base URL is not set (still OpenAI / still
  Claude for `claude-` models).

## Test specification

- Unit (extend `src/container-runner.test.ts`): when the env declares an
  OpenAI-compatible base URL, the spawned container arg list includes an
  `-e OPENAI_BASE_URL=<value>`; when unset, no such arg is emitted.
- Boundary: empty/whitespace base URL is treated as unset (no arg).
- Manual: configure Moonshot base URL + key + a Kimi model id, send one message,
  confirm `[openai-runner] OpenAI request: model=<kimi>` in logs and a coherent
  reply.

## Implementation notes

The gap is real and isolated: `openai-runner.ts:259` reads
`process.env.OPENAI_BASE_URL` (defaulting to `https://api.openai.com`), but
`src/container-runner.ts` never forwards it into the container — it forwards only
`CLAUDE_MODEL` (from `OPENAI_MODEL`, ~line 320-321) and `OPENAI_API_KEY` (~322-323).

Add `OPENAI_BASE_URL` to the `readEnvFile([...])` allowlist in container-runner.ts
(~lines 34-40), then push `-e OPENAI_BASE_URL=${vossEnv.OPENAI_BASE_URL}` alongside
the existing `OPENAI_API_KEY` passthrough (~line 322), guarded by presence. Follow
the exact arg-push pattern already used for VOSS/NOTION/MOLTBOOK. No change needed in
openai-runner.ts — it already honours the env var.

Auth-key caveat to keep in mind: `callOpenAI` (openai-runner.ts:260) falls back to
`ANTHROPIC_API_KEY` if `OPENAI_API_KEY` is absent. Load the Moonshot key as
`OPENAI_API_KEY`; if a stale `ANTHROPIC_API_KEY` is also present in a partial config,
a missing `OPENAI_API_KEY` would silently misroute auth. Not a code change, just a
config gotcha to verify during the manual check.
